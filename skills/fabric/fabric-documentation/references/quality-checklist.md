# Fabric Documentation Quality Checklist

## Innhold

- Dokumentet sier tydelig om det er forslag, arbeidsnotat, MVP, produksjonsdokumentasjon eller runbook.
- Målgruppe, eier og beslutningsstatus er synlig.
- Fakta er skilt fra antakelser og anbefalinger.
- Kilder og hentetidspunkt er oppgitt når dokumentet bygger på ekstern dokumentasjon.

## Fabric Og Power BI

- Fabric item-type, workspace, miljø og avhengigheter er dokumentert.
- Git-/repo-plassering er forklart.
- Semantic model-dokumentasjon angir faktatabeller, dimensjoner, relasjoner, målinger, RLS/OLS og refresh.
- Rapportdokumentasjon angir sider, navigasjon, filtre, sentrale visualer og testpunkter.
- PBIP/TMDL-dokumentasjon bygger på faktiske filer, ikke bare UI-antakelser.

## Data Og Modell

- Radkorn er dokumentert for alle faktatabeller.
- Nøkler, naturlige koder, surrogate keys og komposittnøkler er forklart.
- Historikk/SCD er eksplisitt behandlet.
- Ikke-additive felt er merket.
- Datakvalitetsregler og avstemmingspunkter er konkrete.

## Sikkerhet Og Forvaltning

- Personvern, tilgang, sensitivitet, dataminimering og lagring er vurdert.
- Refresh/SLA, eier, support og feilhåndtering er beskrevet.
- Endringsprosess, test og produksjonssetting er tydelig.
- Kjente begrensninger og videre arbeid er ærlig beskrevet.
