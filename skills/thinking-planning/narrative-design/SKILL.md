# Narrative Design

Use this when the task is to make work understandable, persuasive, teachable,
or decision-ready. The output should help the user do the work and understand
why the structure works.

## Core Workflow

1. Identify the communication job: inform, decide, align, persuade, teach,
   pitch, or prepare for a meeting.
2. Define the audience: role, prior knowledge, concern, decision power, time,
   likely objections, and what they must do after the communication.
3. Write the narrative contract in one sentence:
   `Because [situation/pressure], this audience must understand/decide/do [action].`
4. Choose one spine:
   - **Decision**: situation -> complication -> options -> recommendation -> ask.
   - **Data**: context -> finding -> evidence -> implication -> action.
   - **Change**: what is -> what could be -> why now -> path -> ask.
   - **Pitch**: problem -> insight -> solution -> proof -> plan -> ask.
   - **Meeting**: desired outcome -> pre-read -> agenda -> decisions -> follow-up.
5. Build an evidence ladder: only include evidence that supports the audience's
   next decision or belief change. Mark assumptions and confidence.
6. Storyboard before writing slides. Use slide headlines as the argument; body
   content should support, not replace, the spoken narrative.
7. Add a brief "why this works" note when useful, especially when the user is
   learning narrative craft.
8. Pressure-test for: unclear ask, weak tension, missing audience relevance,
   unsupported claims, overstuffed slides, hidden decision, and no next step.

## Output Patterns

Prefer concrete artifacts over advice:

- narrative diagnosis
- audience map
- one-sentence main message
- storyline / red thread
- slide-by-slide outline
- data story outline
- meeting agenda and decision ask
- pitch script
- speaker notes
- Q&A / objection handling
- revision plan for an existing deck or memo

When the user asks to create or update files, inspect the existing material
first and preserve its constraints unless the narrative needs a new format.

## Quality Bar

A strong narrative has:

- one clear decision, ask, or belief change
- a real tension between current state and desired state
- audience-specific relevance
- enough proof, not all proof
- visible trade-offs and risks
- clear sequencing from context to action
- an ending that assigns next steps or decision ownership
